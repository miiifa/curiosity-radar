## P0 — 事実の混同を防ぐ

### US-V2-01 一次ソースから情報を発掘する
私は再編集されたニュースより、公式発表・本人の制作物・独自の実験を知りたい。
- AC: 出典・主体・日時・原典リンクを表示し、公式/当事者/二次情報を区別。
- AC: Google NewsやHacker News経由の場合も原典を追う。まとめ記事を無条件でそのままフィード化しない。
- AC: ソース障害や原典未確認時は明示し、事実を作らない。

### US-V2-02 セキュリティの危険度と自分に必要な対応
私は企業被害・漏洩・二次被害について、確度と利用者への影響を知りたい。
- AC: 脆弱性と実際の侵害、確定と調査中、被害日と公表日を分離。
- AC: 二次被害への注意を示し、カード停止・PW変更などは必要条件を確かめる。
- AC: 関連する公的注意喚起と被害企業の公表にリンクできる。

## P1 — 発見と使い道

### US-V2-03 六つのジャンルを読みたい
旅行/イベント、お得情報、技術・GitHub・AI・Qiita、セキュリティ、流行、収益化アイデアを表示。
- AC: 各ジャンルに一次情報を探索する方法を実装。未接続ジャンルは未収集と明示。
- AC: 旅行は開催日・申込期限、お得は利用条件・対象地域・費用を判別可能。

### US-V2-04 面白い小型OSSやAIの工夫を発見
私は巨大・有名リポジトリだけでなく新規・意外なOSSやプロンプト実験がほしい。
- AC: 星の総数だけでなく増分の計測期間、新規性、用途、ライセンスと更新状況を表示。
- AC: プロンプトの成果/モデルの性能は出典と再現可能性を明示し、数字を捏造しない。

### US-V2-05 記事の中身をわくわくしながら知りたい
私はカードを開くと独自の概要、ひとこと、キーワード、5軸評価を見たい。
- AC: 詳細画面は確認済み/考察/未確認に分離。
- AC: 評価の理由が読める。欠損は未評価。情報の信頼性や被害緊急性は★と別欄。
- AC: 元記事へのリンクを常に使える。

### US-V2-06 ChatGPTで深い議論を続けたい
私は発見した話題をコピーしてChatGPTに渡し、考察を始めたい。
- AC: 原典URL・概要・論点・不明点・問いを含む短いコンテキストを作成。
- AC: コピー・ChatGPT起動の導線。自動送信したと誤表示しない。
- AC: Web Share APIは任意の追加案。失敗時にコピー経路を残す。

### US-V2-07 ミーハーでない偶然の出会いがほしい
私は関心に近い話題だけでなく、意外な記事も読みたい。
- AC: ジャンル分散と探索枠の設定がある。
- AC: 個人おすすめ度と情報の根拠の強さを混ぜない。

### US-V2-08 収益化の種を現実的に検証
私は技術を使って稼ぐ仮説について「やってみたい」から「顧客検証」まで考えたい。
- AC: 顧客課題、競合、ライセンス、費用、実験方法、撤退条件を提示。
- AC: 利益率/売上/需要は証拠がない限り仮説とラベル表示。

## P2 — AIが記事を理解する

### US-V2-09 独自のAI要約を安全に使う
- AC: 原典で裏付けられた事実とAIの考察を構造化して保存。
- AC: APIキーを公開しない、費用上限を設ける、要約不能時は原典説明へフォールバック。
- AC: 金額・日付・被害・対象者条件の出典整合テストを行う。

## 品質ゲート
各ジャンルから実記事5件のサンプルを抽出し、原典と日付、読者にとっての発見性、説明の誤解の少なさ、ChatGPTへ渡した際の文脈を手動検証する。数値化された指標や完了宣言には再現できる証拠を添える。
