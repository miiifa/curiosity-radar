# 重複・検索・表示順の契約（PR-03）

## URL比較と元情報の保持

比較用URLだけを正規化し、実際に開く `url` と既存のID生成方法は変えない。HTTP取得・リダイレクト解決・外部ページの自動巡回は追加しない。

- ホスト名を小文字化し、HTTPの80／HTTPSの443という既定ポートを省く。末尾スラッシュを比較上は省く（ルートは `/`）。
- 通常のアンカーを除き、`utm_*`、`fbclid`、`gclid` を除く。`#/...` / `#!...` の画面ルートは保持する。
- 未知のクエリ名・値・エンコード・空値と裸のフラグを保持する。デコード後の名前が一意のキーは比較用に並べ替え、同じ名前が複数ある場合（`id`と`%69d`、`a+b`と`a%20b`を含む）は元の順序を維持する。クエリ値とキーの元の表記は書き換えない。HTTP/HTTPS、非標準ポート、言語・記事ID・ページ番号、エンコードされたパスを同一視しない。

通常のニュースはカテゴリをまたいで同じ比較URLを1カードへ整理する。GitHubリポジトリ、収益仮説、通常ニュースは別の目的なので互いに統合しない。

代表はスコアの高い記事、同点なら原典日時の新しい記事、その次はID順。今回取得した記事と前回記事が一致する場合は、前回の高スコアで今回の観測を上書きしない。

v1互換の任意フィールドを使う。

| フィールド | 用途 |
|---|---|
| `aliases` | 統合前のID。以前の保存・既読を代表IDへ引き継ぐ |
| `categories` | 複数のニュースカテゴリ。各カテゴリで検索・表示できる |
| `duplicates` | 統合前のID・元URL・元見出し・出典・カテゴリ・原典日時 |
| `related` | 下記の似た見出し候補。最大3リンク。統合の根拠にはしない |

代表が変わっても前回の別IDを保持する。保存／既読はブラウザー内で代表IDへ変換し、重複を除く。フィードにない保存IDを勝手に消さない。別の現行記事IDを別名にするなど、衝突するID対応はJSON検証で拒否する。個人の保存・既読・重みを公開JSONへ送ることはない。

複数カテゴリの記事は総数では1件、カテゴリ別件数では各カテゴリに含む。そのためカテゴリ件数の合計は総数と一致するとは限らない。カテゴリを選択した画面のピルは選んだカテゴリを使い、ほかの所属もタグ表示する。元の掲載元・リンクは折りたたみで確認できる。

## 別URLの似た見出し

Unicode NFKC・大文字小文字・空白を揃えた見出しが一致し、12文字以上で、両方の原典日時が判明し48時間以内の通常ニュースを候補にする。GitHub・収益仮説は対象外。候補記事を削除・自動統合せず「似た見出し（同じ記事とは未確認）」と表示する。短い定型見出し、日時不明、48時間超を候補にしない。以前の候補情報は最終採用記事から毎回作り直す。

これは意味を理解した関連記事判定ではない。Google Newsの不透明な記事IDや、未知の追跡パラメータを独断で解決しない。異なるURLにある同一記事をすべて発見できるわけではない。

## 検索・フィルタ・並べ替え

- 検索はNFKC・大文字小文字・空白を揃え、空白で分けた語のAND検索。タイトル・概要・出典・推薦理由・タグ・重複元の見出し／出典を文字列として調べる。入力を正規表現やHTMLとして実行しない。
- カテゴリ、保存一覧、未読、検索は共通の処理で組み合わせる。未読は統合前IDから引き継いだ既読も除く。
- 新着順は原典日時の降順、日時不明は最後。同点は重み付きスコア、その次はID順。
- 注目度順はGitHubならスター数、その他は記事の独自スコア。ゼロを欠損や50点として扱わない。同点は重み付きスコア・原典日時・IDで決める。
- おすすめ順の基本は `item.score × (0.50 + weight × 0.17)`。複数カテゴリの記事は所属カテゴリの最大重みを使う。重みは1〜5の整数、無効な設定は既存のカテゴリ初期値へ戻す。
- 検索・保存一覧ではおすすめの強制混合を行わない。明示的な新着順・注目度順も混ぜない。
- それ以外のおすすめ順ではPR-02のGitHub候補枠を混ぜる。全カテゴリ表示では、ほかの主カテゴリの候補がある限り同じ主カテゴリを3件以上連続させない。候補が1カテゴリしか残らなければ続けて表示する。枠内の順序は維持する。
- カテゴリや保存一覧への移動は従来どおり検索・未読条件を解除する。「条件をリセット」はカテゴリ・検索・未読・保存一覧を解除し、ユーザーの並べ替え選択と興味の重みは維持する。

おすすめ順は単純な点数降順ではなく、ソースの信用度を表すものでもない。画面に並べ替えの意味と「独自スコア（参考値）」を表示する。重み・保存・既読はlocalStorageにだけ保存する。

## 検証と残る制約

- fixtureで追跡パラメータ・ポート・末尾スラッシュの3変種を1件に整理し、元URLと出典・旧IDを維持することを確認。
- 記事ID・ページ番号・言語・プロトコル・非標準ポート・SPAルート・重複キー順序・パスエンコード・裸フラグ・クエリ値エンコードの10組は統合しない。
- 別URLの同見出しは2記事のまま候補表示。別日・短い定型見出し・日時不明も削除しない。これらの既知の正解を持つfixtureでは意図しない統合は0件。一般的な誤統合率を推定した結果ではない。
- 既存の公開スナップショット360件を読み取りだけで評価したところ、新たなURL統合は0件、似た見出し候補を持つカードは6件。候補記事の本文・同一事象性は外部で確認していない。
- 末尾スラッシュや既知の追跡パラメータでも、特殊なサイトでは内容が変わる可能性がある。本文同一性は未検証で、元リンクを保持して確認可能にする。未知のパラメータを削除する拡張や見出しの曖昧一致は、このPRでは行わない。
- 元データの正確性・推薦品質・好みへの適合性、Android実機は別途確認が必要。旧キャッシュには新しい重複情報がない場合があり、新しい収集後に反映される。
