# 情報源の取得状況・原典表示（PR-04）

## 取得状況の記録

既存の12 RSS・4 GitHub検索・CISA KEV・Hacker Newsの計18取得処理を記録する。外部リクエスト数やスケジュールは増やさない。取得先の設定は既存どおりで、新しい情報源や通知サービスは追加しない。

収集ジョブのログでは `SOURCE_HEALTH` に続くJSONで、取得元の固定ID・名前・公開URL、状態、取得候補数、確認日時、最終成功日時、保存履歴での連続取得エラー数、履歴の有無、短いエラー分類を確認できる。例外本文・レスポンス本文・認証ヘッダーを記録しない。取得候補数は重複整理・ランキング前の数で、配信件数とは異なる。

- `ok`: フィード／APIの取得・検証に成功。最近の対象記事が0件の場合もある。「新しい記事があった」「内容が正しい」を意味しない。
- `partial`: GitHub検索の `incomplete_results`、一部不正なCVEレコードなど、有効なデータはあるが完全な成功とは扱えない。
- `failed`: 取得・パース失敗、空RSS、全件日時不明、利用可能なカタログデータがない場合など。空の検索結果は提供元の停止と断定しない。
- エラーがある観測（partialを含む）で連続数を増やし、完全な成功で0へ戻す。2回以上ならGitHub Actionsにwarningを出す。HTTP内部再試行は別の観測回数に数えない。
- 最終成功日時はその取得処理が完全に成功した観測日時。記事の掲載日・KEV追加日・スナップショット生成日時とは別。

## 公開ニュースと独立した履歴

`data/.source-health.json` に公開可能な診断情報だけを原子的に保存する。このファイルはGit管理・Pages成果物から除外する。秘密情報の保管場所として使わない。

mainのcollectジョブでGitHub公式の `actions/cache/restore@v4` / `actions/cache/save@v4` を使い、OS・履歴形式v1・run ID・attemptのキーで前回履歴を復元／保存する。保存は `always()` とファイル存在条件で行い、全取得失敗時にも実行する。PRのtestジョブはこれらを実行しない。ジョブ権限とPages公開条件は維持する。

- 成功／部分成功でニュースを公開するときだけ、当該収集の `source_health` をnews.jsonにも含める。画面の「情報源の取得状況」はこの**最終公開収集時点**の記録であり、リアルタイムの死活監視ではない。
- 全取得失敗・利用可能記事なしではnews.jsonを変更せず終了コード1。直前の公開サイトも保持する。一方、作業用履歴とログは更新し、次回の連続エラー検知に使う。全失敗回の状況はActionsログで確認する。
- キャッシュなし・破損・未対応形式なら不明な過去を0回と決めつけない。確認できた観測から数え、「それ以前は未確認」と表示する。公開スナップショットにある最終成功日時は利用できるが、デモの記録は実測履歴に使わない。
- キャッシュより新しい公開済み記録があるときは新しい方を使い、キャッシュ保存失敗後の古い状態への巻き戻りを避ける。
- キャッシュの無効化・削除・失効、ジョブ中断、状態保存失敗では観測に抜けがあり得る。連続数は**保存された観測履歴**に基づく。完全な稼働率や通知の保証ではない。
- 履歴ファイル保存・GitHubキャッシュの障害はwarningとして報告し、有効なニュースの配信は妨げない。ニュース検証や収集失敗の終了コードを成功扱いに変えることはしない。

## 取得元の属性

任意の `source_kind` / `source_url` で検索結果RSS、提供元の公式フィード、研究ブログ、公式カタログ、公開APIを区別する。これは取得方法・提供元の属性であり、内容の信頼度や独立検証済みという評価ではない。

Google Newsの検索結果を公式発表と見せず、リンク先の発信者・内容を確認するよう表示する。RSSの抜粋を自動要約とは呼ばない。既存データに属性がなければ未確認と表示する。取得元リンクは実際に使う公開URLで、元の記事URLは引き続き保持する。重複元の取得元属性も保持する。

## セキュリティ・CISA KEV

- RSS中のCVE表記は正規形式の識別子として抽出するだけで、存在・悪用・利用者への影響を確認したことにはしない。
- CISA KEVは公式カタログに載った悪用事例を示す。CVE形式・カタログ日付を検証し、提供元・製品・requiredActionを原典の記述として表示する。欠損は「未確認」。独自のベンダーURLは創作しない。
- `security.exploitation_status=listed_in_kev` と `user_impact=not_assessed` を区別する。利用製品・バージョン・端末の調査はしておらず、「この端末に影響あり」と生成しない。公開JSONでそのような個人評価を受け入れない。
- `dateAdded` はKEVカタログへの追加日で、攻撃日・脆弱性の公表日ではない。日付だけの情報なので、端末のタイムゾーンで前日にずれないよう暦日で表示する。
- 互換性のため既存のNVDリンク・ID・publishedを維持し、追加日の原表記を任意フィールドで保持する。CISAの元カタログにもアクセスできる。publishedの午前0時は既存ソート互換の表現であり、実際の攻撃時刻ではない。
- 一部レコード不正は有効データを残してpartial、全件不正・不正な外形・空カタログはfailed。例外本文は公開しない。

## 旅行

現行の旅行取得元はGoogle News検索であり、地域・見頃・営業・営業時間・料金の一次情報を構造化して検証する接続はない。このPRでは確認済みの地域／季節／料金等を生成せず、原典での確認を促す。US-15の地域・見どころの充実まで完了したとは扱わない。

「関東」は取得クエリの条件だったため、「検索条件:関東」と表示し、実際の記事の地域と混同しない。見出し・抜粋に「沖縄」「春」「無料」「9時〜17時」があっても、確認済みの所在地・季節・価格・営業時間としては出力しない。今後、利用条件と原典を確認できる情報源を導入する場合は別の狭い変更で扱う。

## 検証範囲

fixtureで18取得処理の正常な一括収集、全失敗2回でもnews.jsonのバイト列・更新日時が不変で履歴のみ進むこと、成功で連続数がリセットされること、履歴欠損・破損・保存失敗、部分結果、CVE形式・追加日・欠損製品・利用者影響未確認を確認する。

ブラウザーでは東京／ロサンゼルスの400px／1440pxでKEV暦日が変わらず、連続エラーと原典属性・旅行の未確認表示が読めることを確認する。既存のオフライン・重複整理・検索・保存の回帰も行う。実GitHubキャッシュを含む新workflow・実情報源の取得・Pages・Android実機の確認はマージ後に必要。
