# 設定と保存の持ち運び（PR-08a）

US-23 / AC-23の、同期サーバーを使わないローカルJSON方式。既存の重みと保存を別ブラウザーへ持ち運ぶ。PR-08の評価ボタン・反応学習は別の小さな変更で扱う。PR-07のLLM解説はプロバイダ・月額上限・データ取扱いの合意が必要なため保留する。

## 使い方

1. 設定を開き「JSONを書き出す」で`curiosity-radar-settings-v1.json`を保存する。
2. 別のブラウザーで設定を開き「JSONを読み込む」からファイルを選ぶ。
3. カテゴリごとの重み、保存ID件数と現在の記事に一致する件数を確認して「確認して適用」を押す。取り消し・画面を閉じる操作では適用しない。

適用時は重みを置き換え、保存は既存のIDとの和集合にする。既読は読み書きしない。エイリアスは現在の正規IDへ合わせ、現在のフィードにないIDも保持する。記事本文を持ち運ぶものではなく、古い記事が現在のフィードにない場合は保存一覧に再表示できない。保存件数にはこうしたIDも含まれる。

「初期設定に戻す」は従来どおり重みだけを戻す。保存や既読を削除しない。取り込み前の重みへ戻す場合は、先にその端末で書き出したファイルを読み込む。保存は追加方式のため、取り込んだ保存を外すときは各記事の保存ボタンで解除する。

## ファイルの契約とプライバシー

- `format: "curiosity-radar-preferences"`、`version: 1`、全7カテゴリの`weights`、`bookmarks`だけを受け入れる。重みは整数1〜5。追加の未知フィールドは拒否する。
- 保存IDは非空文字列、空白・制御文字なし、1つ200文字以内、読み込むファイルと追加後の保存はそれぞれ5000件以内。重複は整理する。
- ファイルはUTF-8で1 MiB以内。バージョン違い、壊れたJSON、不正な値や過大ファイルは適用せずエラーを表示する。統合後も書き出せるよう、保存IDの統合後のJSON容量も同じ上限で検証する。書き出しは余白を省いたJSONとする。
- 記事のタイトル・本文・URL、既読、他のローカル設定・Cookie・認証情報は書き出さない。保存IDと重みでも興味や行動を表すため、ファイルを公開GitHub・共有ログへ置かない。
- 選んだファイルはブラウザー内で読み、ダウンロードにはBlobを使う。アップロード先・API・同期・アカウントは追加しない。利用者が自分でファイルを別端末へ運ぶ。
- ファイル内のIDや元のファイル名をHTMLに展開しない。確認画面には固定カテゴリ名・数値だけを出す。

## 失敗時

確認画面を表示するだけではlocalStorageを書き換えない。閉じる・取り消し・別ファイル選択は進行中の読み込みを無効化する。適用ボタンを押した時点の保存と統合してから検証する。

適用時は既存の2キーだけを書き換え、書き込みが失敗したら変更済みのキーを元の生データに戻す。読み取り不可・容量不足を成功と表示しない。Web Storageには複数キーのトランザクションがないため、復元自体が拒否された場合は完全復元を保証できない。その場合は一部変更の可能性を持続表示し、読める範囲の保存状態を画面へ反映する。既読キーは触らない。保存は追加方式で、既存IDの一括削除は行わない。

ブラウザーテストは合成ファイルのみを使用し、ローカルの実ダウンロード・ファイル選択・プレビュー・取り消し・統合・再読み込み・不正ファイル・遅延した読み込みの破棄・保存失敗と復元失敗を確認する。Android実機のファイル選択・ダウンロード、OS間のファイル移動、実際の読み上げは未検証。別端末の自動同期や別タブ間のリアルタイム同期は対象外。

Service Workerの静的キャッシュはv8。収集・公開JSON・推薦式・既存のlocalStorageキーは変更しない。
