- 2026-10-23 時点のGitHubリポジトリを確認した記録
- 区別: **確認した事実 / そこからの評価・提案 / 未検証**

- 汎用化したルール: [PROJECT_CREATION_PLAYBOOK.md](PROJECT_CREATION_PLAYBOOK.md)

## 1. 初動で機能したこと
- 個人のアイデアから、ユーザーストーリー・システム設計・AGENTS.md・実装計画を作成し、Webアプリ/自動収集/PWA/公開機能を備えるGitHubリポジトリへ短期間で到達した。
- GitHub Actionsで少なくとも一部の公開ジョブが**success**になっていること、Pythonテスト・収集・Pages配信の実行履歴があることを確認した。
- 公開データと個人設定の分離、一次情報重視、事実/推測/アイデアの識別、外部サービスの規約遵守を明文化できた。
- 利用しながらジャンル、情報ソース、記事の考察体験という**本当に重視したい価値**が浮かび、新要件を独立文書で明文化できた。

**評価**: 「まず触れるものを作る」というプロトタイピングの速度は維持すべき。初動の成功は、記事選定精度や日々の利用価値まで証明したわけではない。

## 2. 検証した改善点

| P2 | AGENTS.mdが運用ルールとv2プロダクト仕様を多く含み、指示が長くなっている | 都度自動読込される指示が増え、作業に無関係な内容が読まれやすい | （ChatGPT/Codex）AGENTS.mdは不可欠な不変条件と関連ドキュメントへのリンク中心に整理。詳細要件は仕様書に一元化 | 簡単な変更で不要な大量読込がなく、重要な不変条件を維持 |

- 各改善策のオーナー、優先順位、導入の可否は実装前に確認する。無料プランで利用できないブランチ保護・承認ルールを必須条件として断定しない。

## 3. まだ検証していないこと
- 本番サイト上の各ボタンがAndroid・PC両方で継続して正常動作するか。
- ニュース283件の内容が一次情報であり、正確で面白く、期限切れの混在がないか。
- 定期実行が長期間安定しているか（初回成功と継続稼働は別）。
- 実際のAPI制限、LLM要約費用、各データ取得先の最新の再配布条件。
- v2の新設計（記事詳細・5軸評価・ChatGPTへの考察引継ぎ）は未実装であり、現在の成果ではない。

## 4. 次の3つの実行順
1. **まず運用ガードを作る**：PR確認・検証/配信の分離・main誤更新防止を小さなPRで実施。
2. **次に発見品質を計測する**：各ジャンルの実記事の原典性・時刻・おすすめ度を手動監査し、情報源の採用基準を見直す。
3. **最後に体験を深める**：記事詳細、5軸採点、コピー→ChatGPTへ議論引継ぎ、必要に応じてLLM要約。

**止め時も設計する:** MVPの利用頻度が低い場合、AI機能や情報源を増やす前に「ユーザーが実際に記事を開きたくなったか」を評価する。

## 5. 次回の改善が成功したかを測る3指標（導入後に測定）
- 変更をPRでレビューした割合、テスト失敗をmainに持ち込んだ件数。
- データに原典がある割合、古い/不明/重複の割合、ユーザーが「試したい・考えたい」と評価した記事の割合。
- 収集1回の成功率・費用・所要、公開失敗時の復旧容易性。

この文書自体は**レビュー結果と改善提案**であり、上記の仕組みを実装した証拠ではない。
