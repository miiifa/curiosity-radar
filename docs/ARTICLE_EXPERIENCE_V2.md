
# Curiosity Radar v2 — 記事詳細とChatGPTへの考察引き継ぎ

- ID: CR-ARTICLE-002 / 2026-10-23
- Status: **設計・未実装**。未確認のChatGPTアプリ連携を実装済みと主張しない。

## 詳細画面の順序
1. **発見した一言**：読む価値を短く具体的に。誇大表現は不要。
2. **原典表示**：発信者、一次情報分類（公式/当事者投稿/未検証）、公表日時、最終更新、記事URL。
3. **30秒の概要**：確認できた要点を2〜4文で。ソース側の説明文をそのまま整形した場合、「AI独自要約」と呼ばない。
4. **ユーザーへのひとこと**：いまの関心とつながる意外な用途や行動案を1〜2文。個人の細かい履歴を公にしない。
5. **5段階評価**：発見度、関連度、行動しやすさ、実利、考察の余地を各1〜5、証拠不足は未評価。軸を押すと評価理由と確度を表示。別領域で情報の確度と緊急性を表示。
6. **確認済み / 仮説・考察 / 未確認**：厳密に区分。金額や日付は必ず原典と照合。
7. **キーワード**：3〜7語。必要なら用語の一行説明と関連リンク。
8. **考察の問い**：反論、未知の前提、別視点、試す方法、さらに面白くなる仮説を最大3個。
9. **アクション**：「元記事」「保存」「ChatGPTで考察」を最下部に固定。

## ChatGPTへの引き継ぎ: MVPの確実な手段
- 「ChatGPTで考察」押下時、下記の議論用コンテキストをクリップボードにコピーする。**成功を確認できた場合のみコピー成功の表示**。
- 画面に「ChatGPTを開く」を表示し、https://chatgpt.com/ を開く。ブラウザー/Androidアプリが起動するかは端末設定次第。ユーザーが新規チャットに貼り付けて送信する。
- 「共有」メニューはWeb Share API (navigator.share) を利用可能なら追加候補。ただし共有先ChatGPTの扱いは実機で検証、保証しない。
- 公式に確認できないディープリンクのクエリによる本文自動入力や自動送信は採用しない。将来公式に対応した場合、別ADRで設計する。
- 権限の問題でコピーできない場合はテキスト選択可能な入力欄に全文を表示する。
- ChatGPT APIを用いたアプリ内チャットは別の選択肢。認証、API費用、会話保存、プライバシー、サーバーが必要になるためMVP範囲外。

## 議論用コピーのフォーマット
Curiosity Radarの記事から会話したいです。

【タイトル】<記事タイトル>
【原典】<URL>
【発信元と公開日】<主体> / <日時>
【確認できた概要】<短い説明と事実>
【この話題を私にすすめる理由】<簡潔な評価>
【アプリ側の仮説】<推論と明示>
【不明点】<確認すべきこと>
【キーワード】<3〜7語>
【話したいこと】<問い>

確認された事実、発信者の主張、推論、未確認事項を混同せずに議論してください。必要なら原典を再確認し、反証も含めて考えてください。最後に具体的な次の行動を示してください。

上限はおおむね1500〜2000字。原文全文、機密情報、閲覧履歴、非公開の個人情報は送信しない。

## 独自要約の段階的実装
- Phase 1: 原典RSS/APIの短い説明とタグを整形。文章の出所を明示。推論を事実欄へ入れない。
- Phase 2: 出典が取得可能なもののみLLMで独自要約・見立てを生成。GitHub Actions等のサーバー側にAPIキーを配置。秘密情報をPagesに露出しない。
- LLM出力に確認済みの事実、推論、未確認点、出典、使用モデル、生成時刻を別フィールドで保存。古い記事の更新にも追随。
- 日次費用上限、キャッシュ、プロンプトインジェクション対策、タイムアウト/失敗時フォールバックを設ける。
- 数字、金額、日程、被害数、資格条件の誤記は掲載保留。元記事の本文を許可なく大量保存しない。

## 5段階の採点例（架空記事）
「週末限定の特別公開イベント」: 発見度5、関連度4、行動しやすさ2、実利未評価、考察の余地4。
ひとこと: 「気になるけど、申込や交通費を確認してから候補に入れたい。」
※ 実際のイベントやその評価を示すものではない。

## 受入基準
- 375/430pxのスマホとPCで詳細が崩れない。キーボード操作、コピー失敗、戻る操作をテスト。
- ソース無しで「確認済み」と表示しない。曖昧なデータは未確認/未評価。
- 記事タイトル・URL等を安全にエスケープして描画。
- セキュリティ・旅行・お得の期限や条件が一覧/詳細/コピーで矛盾しない。
