# モックに沿ったUI改修

参照: [レビュー済みモック](mockups/v2-reviewed-ui-reference.jpg)、[v2ストーリー](USER_STORIES_V2.md)。画像の例示データより正式仕様を優先する。

## 小さなPRで進める順序

1. **UI-01 ホームの外観**: 白基調・青アクセント、検索と記事を優先。大きな導入文・統計を外し、取得情報は開いて確認。写真がない記事は写真なしで成立させる。
2. **UI-02 6ジャンルへの表示整理**: 既存収集データの対応を明記し、未接続のお得情報は未収集と表示。GitHub・AI、流行・趣味を表示上のグループへまとめ、既存記事・保存・重みを削除しない。
3. **UI-03 記事詳細**: 原典・概要・ひとこと・行動を上部へ。事実／解釈／未確認と5軸評価を下部へ。根拠がない評価は未評価。戻る・検索条件・スクロール位置・保存を検証する。
4. **UI-04 ChatGPTへの引き継ぎ**: 公開記事から短い相談文を作り、コピーと明示的なChatGPT起動を提供。失敗時は手動コピー。自動入力・送信、アプリ内APIチャットは行わない。

各PRでテスト、GitHub AIレビュー、指摘修正と最新コミットの再レビューを行う。指摘がなくCI成功なら、利用者からの包括承認に基づきマージ・公開確認まで進める。スクリーンショットとブラウザー操作、本番確認を区別する。

## UI-01の表示契約

- 注目枠は現在のおすすめ順の最初の候補。検索・保存一覧・明示ソートでは独立した注目枠を出さない。候補がなければ省略する。
- 「今日の注目」は日本時間当日の正常なライブ収集で、エラーなし・ネット接続あり・キャッシュでない場合のみ。古い・部分失敗・オフライン・キャッシュは「前回取得時の注目」。デモは「デモの注目」。記事公開日とは別の判定。
- 出典と日付を残し、リポジトリ指標・原典属性・重複候補・独自スコアは「出典・参考情報」を開いて読む。安全性・旅行情報・収益性の注意を削除しない。
- この段階は既存7カテゴリと既存データを使用。6ジャンルはUI-02で対応する。詳細への遷移とChatGPTは後続PRで受け入れる。
- 表示整理で既存テストの取得情報を確認する際は、実際の利用者と同じく確認欄を開く。検証内容や異常系の条件は維持する。

## 検証と限界

375／430px・PCで、最初の画面に記事の価値と出典が入ること、長い見出し・写真なし・候補なし・古さ・オフラインを確認する。既存の保存・設定持ち運び・検索・キーボード・オフライン復元も回帰確認する。

モックの写真や架空ニュース・数字・認証風バッジを本番記事へ流用しない。LLM・有料API・新しい情報源の追加はこのUI改修に含めない。Android実機のタッチ・読み上げ・PWA更新は別途確認が必要。

## UI-02の対応表

表示上の6ジャンルは旅行・イベント、お得情報、技術・GitHub・AI、セキュリティ、流行・話題、収益化アイデア。技術は既存github/ai、流行はsocial/hobbyの和集合。趣味は削除せず種類フィルターで読める。重複元から付いた複数カテゴリも従来どおり対象になる。

元の7カテゴリの重み・JSON持ち運び形式・保存IDを維持する。お得情報は収集元未接続のため0件と明示する。この変更で一次情報の新規接続や全v2ソース要件が完了したとはしない。旧カテゴリのフィルターAPIも互換維持する。
